# Архитектура «Мой дацан»

Документ растёт вместе с проектом: в конце каждого этапа сюда дописывается, что появилось.

## Из чего состоит приложение

```
            Телефон / браузер                               Сервер (сейчас — ваш Mac, потом VPS)
 ┌──────────────────────────────────┐                ┌─────────────────────────────────────┐
 │ Android APK (WebView)            │                │ server/  Express + TypeScript       │
 │  └ открывает веб-версию user/    │   HTTP /api    │  ├ отдаёт контент (главы, хуралы,   │
 │                                  │ ─────────────► │  │  божества, практики, зурхай)     │
 │ user/  React-приложение          │   только       │  ├ принимает правки от админки      │
 │  └ личные данные — localStorage  │   чтение       │  ├ раз в день парсит зурхай          │
 └──────────────────────────────────┘                │  └ SQLite: server/data/datsan.db     │
                                                     └──────────────▲──────────────────────┘
 ┌──────────────────────────────────┐   HTTP /api + токен           │
 │ admin/  React-приложение         │ ──────────────────────────────┘
 │  └ вход по паролю администратора │   чтение и запись
 └──────────────────────────────────┘
```

**Три приложения в одном репозитории (монорепо):**

| Папка | Что это | Кто пользуется |
|---|---|---|
| `user/` | веб-приложение с 5 вкладками | все пользователи (через браузер или APK) |
| `admin/` | админ-кабинет | только администратор |
| `server/` | API и база данных | `user/` и `admin/` обращаются к нему |
| `shared/` | общие типы TypeScript | чтобы `server` и фронтенды одинаково понимали данные |
| `android/` | Android-обёртка | собирается в APK |
| `content/` | скрипты импорта книги и черновики контента | разработчик |

## Ключевые решения и почему

- **Нет регистрации** → сервер не хранит пользователей, а значит, нечего взломать и украсть.
  Прогресс живёт в `localStorage` телефона. Минус: при удалении приложения прогресс теряется — это осознанный выбор.
- **SQLite** → база — один файл, не нужен отдельный сервер БД. Для контент-приложения этого с запасом.
- **Монорепо** → одна история изменений, один PR может менять и сервер, и экран — проще учиться и проверять.
- **APK как WebView** → одна кодовая база; обновили сайт — обновилось приложение без новой сборки APK.

## Этапы

### Этап 1 — скелет монорепо (v0.1.0)

Что работает: `npm run dev` поднимает три части, они видят друг друга.

```
 npm run dev ──► concurrently
                 ├─ [server] tsx watch server/src/index.ts  → :3001  (Express + SQLite server/data/datsan.db)
                 ├─ [user]   vite (user/)                    → :5173  ─┐
                 └─ [admin]  vite (admin/)                   → :5174  ─┴─ /api/* проксируется на :3001
```

| Часть | Ключевые файлы | Что в ней сейчас |
|---|---|---|
| `shared/` | `types.d.ts` | тип `HealthResponse` — «договор» между сервером и фронтендами |
| `server/` | `src/index.ts` (запуск), `src/app.ts` (маршруты), `src/db.ts` (база) | `GET /api/health`, таблица `app_meta`, тест `app.test.ts` |
| `user/` | `src/App.tsx` (маршруты), `components/BottomNav.tsx`, `index.css` | 5 вкладок-заглушек: Практика · Хуралы · **Философия** · Зурхай · Божества |
| `admin/` | `src/sections.ts` (список разделов), `components/Sidebar.tsx`, `pages/*` | меню разделов слева, рабочая область справа, статус сервера |

Решения этапа:
- `app.ts` отделён от `index.ts`, чтобы тестировать сервер без порта и с базой в памяти (`:memory:`).
- Общие типы — файл объявлений `.d.ts`: он не попадает в сборку сервера и не ломает `rootDir`.
- Одна версия Vite (8) на весь монорепо: разные версии в разных пакетах ломают плагин React.
- `react-router` 7 вместо 6 — в 6-й найдена уязвимость. Правило: после `npm install` смотреть на `found 0 vulnerabilities`.
- Раскладка и размеры — как в «Я стоик» (меню 64px, отступы 24/16/80), палитра своя.

### Этап 2 — админ-кабинет: вход и редактор (v0.2.0)

```
 admin  ── POST /api/admin/login {password} ──► server: verifyPassword(scrypt-хеш из .env)
        ◄────────────── { token } (JWT, 30 дней) ─┘     5 ошибок за 15 мин → 429
 admin  ── POST /api/upload + Bearer <token> ──► requireAdmin ─► multer ─► server/uploads/<имя>.png
 user/admin ── GET /uploads/<имя>.png ─────────► express.static(server/uploads)
```

| Где | Файл | Роль |
|---|---|---|
| server | `src/config.ts` | читает `.env`; без `JWT_SECRET`/`ADMIN_PASSWORD_HASH` сервер не стартует |
| server | `src/auth/password.ts` | `hashPassword` / `verifyPassword` (scrypt, сравнение за постоянное время) |
| server | `src/auth/requireAdmin.ts` | `signAdminToken`, охранник `requireAdmin` — ставить на **каждый** изменяющий маршрут |
| server | `src/routes/admin.ts`, `src/routes/upload.ts` | вход, `/me`, загрузка картинок (JPG/PNG/WebP/GIF, без SVG) |
| server | `src/scripts/admin-password.ts` | `npm run admin:password -w @datsan/server` → строки для `.env` |
| admin | `src/lib/api.ts` | все запросы: токен в заголовке, 401 → выход |
| admin | `src/context/AuthContext.tsx`, `pages/Login.tsx` | состояние входа, экран пароля |
| admin | `components/HtmlEditor.tsx`, `ImageUploadModal.tsx` | редактор с предпросмотром — общий для всех разделов |

Решения этапа:
- Один администратор, без логина — только пароль; пароль в `.env` хранится хешем.
- `createApp(db, config)` получает настройки параметром — в тестах свои пароль, секрет и временная папка загрузок.
- Классы оформления текста: `.mantra` (мантра), `.accent` (выделенный блок), `blockquote` (цитата) —
  их же будет понимать приложение при показе глав, хуралов и божеств.
