# Шпаргалка по Git и GitHub

Пополняется на каждом этапе. Здесь — только то, что мы реально использовали в этом проекте.

## Основные понятия

| Понятие | Простыми словами |
|---|---|
| **Репозиторий** | папка проекта + вся история её изменений |
| **Коммит** | сохранённый снимок изменений с подписью «что и зачем» |
| **Ветка** | параллельная линия истории; правки в ней не трогают `main`, пока их не вольют |
| **`main`** | главная ветка — рабочая, проверенная версия проекта |
| **Remote / `origin`** | копия репозитория на GitHub |
| **Push** | отправить свои коммиты на GitHub |
| **Pull** | забрать новые коммиты с GitHub |
| **Pull Request (PR)** | запрос «влей мою ветку в `main`» — с диффом, обсуждением и проверками |
| **Issue** | задача или проблема на GitHub |
| **Milestone** | веха — набор задач одного этапа |
| **Тег / Release** | метка версии (`v0.1.0`) и страница релиза с файлами |

## Этап 0. Подключение к GitHub

| Команда | Что делает |
|---|---|
| `brew install gh` | ставит GitHub CLI — программу для работы с GitHub из терминала |
| `gh auth login --git-protocol ssh --web` | входит в аккаунт GitHub через браузер и загружает SSH-ключ |
| `ssh -T git@github.com` | проверяет, что GitHub узнаёт ваш компьютер по SSH-ключу |
| `gh auth setup-git` | разрешает git брать «пропуск» (токен) у `gh` — `push` по HTTPS без пароля |
| `gh repo create moy-datsan --private` | создаёт приватный репозиторий на GitHub |
| `git init -b main` | превращает папку в git-репозиторий с главной веткой `main` |
| `git remote add origin <адрес>` | запоминает адрес GitHub под коротким именем `origin` |

> Наш SSH-ключ защищён кодовой фразой, поэтому git работает с GitHub по **HTTPS** через `gh`.
> Оба способа равноценны; HTTPS через `gh` не требует вводить пароль.

## Три шага сохранения: add → commit → push

```
 рабочая папка          «коробка» (staging)          история (коммиты)           GitHub
 ─────────────   git add   ─────────────   git commit   ─────────────   git push   ─────────
  правите файлы  ───────►  что войдёт     ──────────►  снимок с       ─────────►  то же на
                           в коммит                    подписью                   сервере
```

| Команда | Что делает |
|---|---|
| `git status` | показывает, что изменено (красным) и что лежит в коробке (зелёным). **Запускать перед каждым коммитом** |
| `git add <файл>` | положить конкретный файл в коробку |
| `git add .` | положить в коробку **все** изменения в папке (кроме того, что скрывает `.gitignore`) |
| `git commit -m "тип: описание"` | сохранить содержимое коробки как коммит |
| `git push -u origin main` | отправить ветку на GitHub; `-u` связывает её с веткой на GitHub, дальше хватит `git push` |
| `git log --oneline` | список коммитов, по одному в строке |

**Урок этапа 0.** В первый коммит планировали положить 2 файла, а ушли все 7 — потому что после
`git add README.md .gitignore` был выполнен ещё `git add .`. Коммит сохраняет ровно то, что лежит в коробке,
push отправляет ровно то, что сохранено. При этом PDF и `.DS_Store` не попали — их отсеял `.gitignore`.

## Ветки и Pull Request

| Команда | Что делает |
|---|---|
| `git switch -c <ветка>` | создать новую ветку и перейти в неё |
| `git switch main` | вернуться в `main` |
| `git branch` | список веток, текущая отмечена `*` |
| `gh pr create` | открыть Pull Request — запрос «влей мою ветку в `main`» |
| `gh pr merge --squash --delete-branch` | влить PR одним коммитом и удалить ветку |
| `git pull` | забрать с GitHub новые коммиты в текущую ветку |

Имена веток: `feature/<номер-issue>-<кратко>` — новая функция, `fix/…` — исправление, `docs/…` — документы.

## Смотреть изменения

| Команда | Что делает |
|---|---|
| `git diff` | построчно: что изменилось с последнего коммита. `+` — добавлено, `-` — удалено |
| `git diff --stat` | коротко: какие файлы и сколько строк изменилось |
| клавиша `q` | выйти из режима листания (когда внизу терминала стоит `:`) |

## Порядок на GitHub: Issues, Milestones, метки, доска

| Понятие | Простыми словами |
|---|---|
| **Issue (задача)** | карточка «что нужно сделать». Номер: `#2`, `#3`… (общий счётчик с Pull Request'ами) |
| **Milestone (веха)** | этап из roadmap; показывает, сколько его задач закрыто |
| **Label (метка)** | цветной ярлык для фильтра: `книга`, `зурхай`, `сервер`… |
| **Projects (доска)** | колонки Todo → In Progress → Done |
| **`Closes #2`** | фраза в описании PR: при merge GitHub сам закроет задачу #2 и свяжет её с кодом |

| Команда | Что делает |
|---|---|
| `gh issue list` | список открытых задач |
| `gh issue view 2` | посмотреть задачу #2 |

## Если PR влит кнопкой на сайте

`gh pr merge` сам возвращает вас на `main`. После кнопки на сайте — вручную:

| Команда | Что делает |
|---|---|
| `git switch main` | перейти на `main` |
| `git pull` | забрать влитый коммит с GitHub |
| `git branch -D <ветка>` | удалить старую ветку у себя (`-D`, т.к. после squash git не узнаёт свои коммиты) |
| `git fetch --prune` | забыть ветки, которые уже удалены на GitHub |

## Откат изменений — 4 уровня

Чем дальше изменение ушло, тем аккуратнее откат.

| Где изменение | Команда | Что происходит |
|---|---|---|
| **1. Только в файле** | `git restore <файл>` | файл возвращается к версии из последнего коммита; правки **стираются навсегда** |
| **2. В коробке** (после `git add`) | `git restore --staged <файл>` | файл вынимается из коробки; правки **остаются** в файле |
| **3. В коммите, push не было** | `git commit --amend` | дописать коробку в последний коммит и/или поменять его название; коммит получает новый номер |
| | `git reset --soft HEAD~1` | «распаковать» последний коммит обратно в коробку |
| **4. Уже на GitHub / в `main`** | `git revert <коммит>` → PR | новый коммит, отменяющий старый; история не переписывается |

**Главное правило:** `--amend` и `reset` — **только до push**. После push историю не переписываем, а делаем `revert`.

**Страховка:** `git reflog` — дневник всех перемещений на вашем Mac. В нём видны даже коммиты,
заменённые через `--amend` (~90 дней). Правки, которые ни разу не попали в коммит, git не помнит.

## Защита ветки `main`

Репозиторий публичный, `main` защищена на GitHub:
- изменения попадают в `main` **только через Pull Request** — даже у владельца;
- нельзя перезаписать историю (`force push`) и удалить ветку;
- разрешён только **squash merge**, ветка после merge удаляется сама.

> Для приватных репозиториев защита веток на бесплатном тарифе недоступна — поэтому репозиторий сделали публичным.
> Секретов в нём нет и быть не должно: всё секретное перечислено в `.gitignore`.
